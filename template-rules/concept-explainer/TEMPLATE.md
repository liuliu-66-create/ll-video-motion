# 概念解释模板规则

## 用途

用于解释“一个概念是什么、有什么特点、为什么与观众有关”。不承担完整逐字稿，只展示核心概念、简短定义和关键词。

## 构图选择

### 中心放射型 `radial`

适合一个概念对应 2～4 个并列特征。核心概念放在中央的一张撕纸卡上，外围解释直接使用纯文字，不再给每组文字重复添加撕纸底板。

调用合成项：`ConceptExplainerRadialGithub`。

### 上下拆解型 `topdown`

适合“概念 → 定义 → 组成或特征”的层级解释。标题和定义直接排在背景上，下方只使用一整张横向撕纸承载 3 个分栏；01、02、03 是栏目编号，不代表时间流程。

调用合成项：`ConceptExplainerTopDownGithub`。

## 输入内容

- 核心概念：例如 `GitHub`。
- 一句话定义：例如“全球开源代码和项目托管平台”。
- 2～4 个解释关键词。
- 如需数字高亮，将数字拆成前缀、高亮值和后缀。

## 共同规则

- 核心概念必须最先出现。
- 撕纸只用于核心信息或统一的信息承载区，不能给每一个词、每一组文字都套撕纸背景。
- 模板名、分类名、结构说明和验收标签属于素材库元数据，禁止出现在成片中。
- 连接线必须避开文字安全区，不能穿过或垫在文字下方。
- 文字必须和它实际所在的承载区对齐；文字变长时优先缩小字号，不能拉伸纸张。
- 撕纸边缘必须有明显但克制的不规则起伏，不能做成平滑圆角卡片。
- 两种构图的具体坐标、箭头方向和安全区见 `layout.json`。

## 动效顺序

### 中心放射型

中央撕纸卡 → 核心文字 → 三条连接线依次绘制 → 左、右、下方解释依次进入。

### 上下拆解型

顶部概念 → 一句话定义 → 分支连接线 → 横向撕纸信息区 → 三栏内容依次进入。

## 调用

```powershell
npm.cmd run render:concept-radial-github
npm.cmd run render:concept-topdown-github
```

实际使用时修改 `src/Root.tsx` 中对应合成项的文字参数，或复制为新的配置入口；不得修改贴纸坐标。

## 验收

- 第一眼能明确看出核心概念。
- 放射型连接线在文字外停止，不能被文字覆盖。
- 上下拆解型连接线分别落到横向撕纸上方的左、中、右三个位置。
- 横向撕纸的上下边缘可直接看出自然撕裂感，但不能堆叠多层碎纸。
- 画面有明显留白，撕纸只点到为止。
- 成片中不得出现“概念拆解”“放射式解释”“上下拆解式”等内部名称。
