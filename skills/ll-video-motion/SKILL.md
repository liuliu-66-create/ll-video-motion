# 六六视频动效

把用户的中文内容变成一个或多个真实可播放的独立短动效。先判断最终交付物和动效数量，向用户说明方案并等待确认；确认后再为每个内容单元选择模板并生成 MP4。

## 生成前的判断与确认

1. 阅读 [references/planning-boundary.md](references/planning-boundary.md)，先判断用户要的是独立动效素材，还是一条完整视频。
2. 如果用户要完整配音、全程字幕、真实素材和连续镜头组成的完整成片，停止本 Skill 的生成流程，说明边界并推荐使用 `ll-video-edit`。
3. 如果用户要独立动效素材，判断内容应合并为一个动效还是拆成多个动效。不要按句号数量、文字长度或固定上限机械拆分。
4. 渲染前必须给出方案，包括建议动效数量、每个动效使用的原文范围、表达关系、大致画面和预计输出文件数量。
5. 必须等待用户明确确认。用户要求合并、拆开、删除或调整重点时，先更新方案，再次确认；未经确认不得创建配置或渲染视频。

## 确认后的工作流程

1. 运行 `node scripts/catalog.mjs --check`，确认项目和已验证模板可用。
2. 对每个已确认的内容单元分别阅读 [references/selection-guide.md](references/selection-guide.md)，判断内容关系并选择一个 `styleId`。
3. 对每个 `styleId` 分别运行 `node scripts/catalog.mjs --id <styleId>`，只读取对应模板的规则、布局和可编辑字段。不要一次加载全部模板规则。
4. 保留原意，把观众必须看到的内容压缩为模板字段。不得虚构数字、日期、规模、因果或结论。
5. 按 [references/config-format.md](references/config-format.md) 为每个动效保存独立的 UTF-8 JSON 配置。
6. 每个配置都先运行 `node scripts/render.mjs --config <配置绝对路径> --dry-run` 检查模板和字段，再去掉 `--dry-run` 生成 MP4。
7. 分别检查每条视频的规格，并抽取代表帧查看文字溢出、遮挡、贴纸居中和画面内容。技术检查通过不等于用户视觉确认。
8. 按确认方案的顺序返回每条动效的用途、配置路径和 MP4 绝对路径。用户要求修改时，复用对应配置，只改相关字段后重新生成。

用户需要编辑页面时，运行 `node scripts/editor_server.mjs`，再打开渲染结果返回的 `editUrl`。编辑页只展示真实渲染后的 MP4，不使用另一套近似排版冒充预览。

## 多个章节过渡的选样流程

用户明确要一次制作多个章节之间的短过渡时：

1. 先整理用户给出的章节编号和短标题，说明将生成几个独立 MP4；章节不清楚时只确认章节，不先选择模板。
2. 只要用户没有明确指定“样式 A”或“样式 B”，就必须主动运行 `node scripts/playground_server.mjs` 并打开命令输出的 `chooseUrl`，让用户观看“章节过渡”里的真实动态样片。不要等用户提出“打开 Playground”，也不要先问用户是否需要看样式。
3. 用户只需回复“样式 A”或“样式 B”。内部映射为：样式 A = `chapter-transition-dark-banner`；样式 B = `chapter-transition-split-newspaper`。也允许用户明确要求不同章节使用不同样式。
4. 选样后，用日常语言复述章节数量、每章标题、所选样式和预计文件数量，等待用户最终确认，再批量生成。
5. 每个章节单独保存配置并生成一个约 5 秒 MP4，不把多个章节拼成一条视频。

如果章节数字出现断裂、缺块、越界或其他异常，或者章节数字的字体、缩放、遮罩代码被修改，必须先运行 `node scripts/validate_chapter_numbers.mjs`。打开脚本返回的 `contactSheet`，检查 `00–99` 全部章节号均连续、可读且没有越界，再重新渲染用户文件。异常数字不得解释为字体风格，也不得在回归检查前宣布视觉验收通过。

对用户只说“给这几个章节做过渡动画”这类自然表达，也执行以上选样流程。`Playground` 是内部工具名称，不要求用户提前知道或说出这个词。

章节过渡与贯穿全片的顶部目录进度条不是同一功能；本 Skill 当前不生成顶部目录进度条。

## 选择边界

- 只调用目录中 `status=validated` 的模板或变体。
- 先判断列举、流程、对比、关系、概念、数据、选择或真实素材等语义结构，再选择具体构图。
- 原文不适合任何已验证模板时，直接说明不适合；不要把流程硬套成列举，也不要把普通观点编造成数据图表。
- 需要真实录屏、截图、图片或音频的模板，只能使用用户提供或项目中已确认的真实素材。
- 内部分类名、模板名、代码名、验证状态和设计说明不得渲染进视频。
- 不修改 `library.json`、Playground 或模板视觉代码来迁就单次文案。确需扩充模板时，先单独征得用户同意。

## 与完整剪辑的边界

本 Skill 生成一个或多个彼此独立、可供后续剪辑使用的短动效素材，不负责把它们连接成完整视频。动效数量不是边界：即使需要多个素材，只要用户要的仍是独立 MP4，就继续使用本 Skill。

如果用户希望把完整逐字稿制作成带完整配音、全程字幕、真实录屏和连续镜头的成片，应停止当前流程并推荐 `ll-video-edit`。不得仅凭文字较长就自动转交；如果用户明确只想从长文中提取若干独立动效，仍由本 Skill 完成。
