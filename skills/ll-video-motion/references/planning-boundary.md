# 动效拆分、确认与 Skill 边界

## 核心判断

一个动效只承载一种主要内容关系，并让观众在一个短镜头里看懂一个重点。不要按句子数量拆分，也不要预设最多只能生成几个动效。

优先判断用户最终要什么：

- 要一个或多个可以拿去剪辑的独立 MP4：继续使用 `ll-video-motion`。
- 要把完整逐字稿做成包含配音、全程字幕、真实素材和连续镜头的完整成片：推荐 `ll-video-edit`。

文字长度只作为辅助信号，不能单独决定转交。完整逐字稿也可以只提取几个独立动效；较短的文字也可能是在要求制作完整成片。

## 合并为一个动效

满足以下条件时优先合并：

- 内容围绕同一个对象和同一个结论；
- 多句话共同组成同一种关系，例如一个前后对比、一组步骤、一个定义及其组成部分；
- 使用一个模板就能清楚表达；
- 压缩后仍能保留用户原意，并且不会造成文字拥挤。

## 拆成多个动效

出现以下情况时建议拆分：

- 主要关系发生变化，例如从前后对比转为操作流程，再转为数据结果；
- 表达对象或观众需要理解的重点发生变化；
- 某一部分单独拿出来仍是完整观点，并且值得独立强调；
- 同一输入同时包含流程、数据、选择、层级等不同结构；
- 一个模板无法清楚承载全部必要信息。

不要为了增加动效数量，把一句完整观点拆碎；也不要为了少生成文件，把多个不同关系强塞进一个模板。

## 生成前必须展示的方案

无论建议一个还是多个动效，都先用日常语言说明：

```text
这段内容建议制作 N 个动效，确认后预计得到 N 个视频文件。

动效1：<这一段的作用>
使用内容：<对应原文或准确概括>
表达关系：<前后对比／流程／数据结果等>
大致画面：<用户能理解的动画表现，不必暴露内部代码名>

动效2：...

如果这个拆分和表现方式没有问题，请确认；确认后再开始生成。
```

用户提出调整时先更新方案。只有用户明确表示“确认”“可以生成”“按这个做”等，才进入配置和渲染。

## 完整逐字稿的提示话术

当输入看起来是一篇完整逐字稿，而且用户的最终目标不清楚时，使用下面的边界说明：

```text
你提供的内容是一篇完整逐字稿，其中包含开头、观点展开、案例、流程和结尾。

如果只提取其中几个重点制作成独立动效，我可以继续使用 ll-video-motion。

如果你希望把整篇逐字稿做成包含配音、字幕、录屏和多个镜头的完整视频，更适合使用 ll-video-edit。

你需要的是几个独立动效素材，还是把整篇逐字稿做成一条完整视频？
```

不得未经用户选择就自动切换 Skill 或开始完整视频制作。
